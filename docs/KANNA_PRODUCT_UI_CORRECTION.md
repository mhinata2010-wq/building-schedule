# KANNA製品UIに合わせた再設計（前回の誤ったLP解釈を修正）

2026-11-05

## 修正が必要だった原因

以前の `kanna-workspace.css` はKANNA **ランディングページ**から緑色とCTAを抽出しただけで、施工管理アプリの実UIを観察していなかった。結果、Building Scheduleの幅広いサイドバー、大きなグリーンのサマリーヒーロー、オレンジ色ボタン、大きなカードを維持していた。

これでは「KANNAのデザインを模倣して元の機能を載せる」という要望を満たさない。

### 観察→変更

| 項目 | KANNA製品スクリーンショット | 以前のBuilding Schedule | 今回の修正 |
| --- | --- | --- | --- |
| ナビゲーション | 狭いアイコンレール | 252pxのテキストサイドバー | 68pxのアイコンレール。各アイコンにホバー・フォーカス時のツールチップとaria-label |
| トップ | 低い白いヘッダー | 大きめのサマリーヘッダー | 62pxの白いヘッダー + 現在ページのパンくず |
| 案件情報 | 行単位で整理された情報 | 146pxの緑ヒーロー | 82pxの白い案件情報バー。工程数・未完了・進捗を動的算出 |
| 工程表 | 細い行、明るい薄緑バー、グレーのグリッド | 青い強いバーと大きな余白 | 47px行 / 36px日付 / 26px緑バー / 280px工程名列を基本に調整 |
| 進捗 | 案件の基本情報を表で表示 | 大きなサークル中心 | 表形式の工程ダッシュボードを追加し、既存グラフも残す |
| モバイル | 専用アプリのナビ | テキストのサイドドロワー | 端末幅900px以下は既存ドロワーのラベルを表示。タップ操作を維持 |
| 背景・CTA | 白基調＋控えめなグリーン | 巨大な緑背景とオレンジCTA | 白の表・枠、緑の操作CTA、最小限の色 |

## 実装ファイル

- `kanna-product-fidelity.css`：**製品画面を参照した最終上書きレイヤー**。旧`kanna-workspace.css`より後に読み込む。
- `kanna-product-fidelity.js`：アイコンナビのラベル、パンくず、実データを表示する進捗サマリー。
- `index.html`：新しいCSS/JSを後読み込み。元のアプリの編集JS・DOMは削除していない。
- `tests/kanna-full-workspace.test.mjs`：ナビ構造、画面・機能の保持、JS整合性。
- `tests/kanna-workspace.browser.test.mjs`：デスクトップのナビ幅、白い案件バー、緑色ガントバー、PC/スマホのページ操作、スクリーンショット。

## 既存機能の保持

- 今日の工程・次に開始する工程
- 工程のドラッグ作成 / 移動 / 期間変更 / 削除 / 後続工程に影響する変更時の確認
- ミニマップ横スクロール / 日・週・月切替 / ネットワーク図
- 優先度1・2を面積で強調したタスク管理（以前のPR #29）
- 進捗・予定実績差・工程ステータス
- プロジェクト名 / 所在地 / 責任者 / メモ
- CSV / 印刷 / PDF / JSONのバックアップ / 設定 / ヘルプ

## QAの受け入れ条件

1. PC 1440pxで左ナビが約68px、ヘッダーが薄く、案件サマリー背景が白い
2. 工程表は淡い緑のバー、細い区切り線、行と日付が並ぶ
3. ナビアイコンはホバーとキーボードフォーカスでラベルが読める
4. モバイル390pxではメニューが開き、文字ラベルを表示してページ移動できる
5. 進捗表には実データに基づく数字が表示される（架空の件数を入れない）
6. 既存の工程更新やローカル保存の呼び出しは変更しない
7. CIが通るまで本番mainへは変更を反映しない

## 制約・注意

- KANNAのブランド名・ロゴ・写真・商用ソースを転載していないため、**ピクセル単位の複製ではない**。
- KANNAにある案件ボードやクラウド共同編集を、既存Building Scheduleが実装済みであるかのようには表示していない。
- Supabase・Firebase・QR共有は未接続。現在の工程データはブラウザ端末保存のまま。
- 現行KANNAの非公開画面の内部構造まで知ることはできない。一次ソースのスクリーンショットに確認できる視覚仕様だけで設計した。
- Chromeデスクトップとモバイルエミュレーションの試験結果、タッチによるバー編集やiPhone Safariは別々に管理する。
